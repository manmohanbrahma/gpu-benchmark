LLM Serving Benchmark

Summary

What was measured

Load generator: vllm bench serve, random token prompts, --ignore-eos so every request generates exactly the requested output length, a warm-up before each server, prompts per run = 4 × concurrency (minimum 8). TTFT = time to first token, TPOT = time per output token after the first, E2E = whole request. Dashed lines are non-benchmark settings profiles (for example NAI defaults); dotted lines are external endpoints.

Runtime parameters

What each engine reported at start-up, the exact server command line, and the pod settings. KV cache is the token capacity left after the weights; full-length requests is how many requests at the configured maximum context fit at once.

Metric

Output quality

Output parity with the reference

200 fixed prompts (100 GSM8K, 100 IFEval), greedy, 256 new tokens. Free-running columns compare generated tokens directly. Teacher-forced columns replay the reference output through each stack and compare next-token distributions over the top 20 candidates, which separates numeric differences from divergence that compounds after one changed token. The reference's self-repeat row is the noise floor.
